# Alphadome Forge Operating Rules

This repository is a revenue system first and a codebase second.

## Default Objective

Convert Copilot time into deployable software that can be shown, sold, and paid for quickly.

## Priorities

1. Revenue proximity
2. Reuse of existing Alphadome modules
3. Demo value for a real buyer
4. Deployment speed
5. Tenant isolation, security, and reliability

## Working Rules

- Start with repository archaeology before proposing new implementation work.
- Prefer adapting existing workflows, integrations, and UI surfaces over rebuilding them.
- Choose the smallest shippable slice that can be demoed to a prospect within 7 days.
- Keep the work tied to paid pilots, contracts, or near-term customer conversations.
- Avoid greenfield platform rewrites, generic abstractions, and architecture that does not shorten time to revenue.
- When a request is broad, narrow it to one buyer, one workflow, one deployable asset, and one measurable outcome.

## Default Output Shape

When asked to plan or build something, always include:

- target buyer
- workflow being solved
- reusable code or docs already present in this repo
- minimal implementation slice
- revenue impact
- main technical risks
- next validation step

## Revenue Bias

Prefer products and demos that help sell:

- quotation automation
- tender intelligence
- lead qualification and follow-up
- WhatsApp order handling
- M-Pesa/payment flow automation
- operations monitoring and exception handling

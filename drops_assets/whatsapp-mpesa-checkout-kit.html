Tenant Scan to Pay — merchant wallet + client wallet

Surface: admin/tenant_dashboard.html → Store → Scan to Pay Backend: utils/scanPay.js (rules) + server.js (routes) Customer page: public/pay.html served at /pay/t/<templateId> Status: built 2026-10-25 on the QR + STK stack already live for Kassangas.

What a tenant can do

| Direction | Action | Endpoint | |---|---|---| | Collect | Create a reusable payment link (item + amount) | POST /tenant/scan-pay/links | | Collect | Show the QR / copy the link / download the QR as a PNG | client-side (/vendor/qrcode.min.js + /vendor/qr-poster.js) | | Collect | Prompt a named customer's phone for a link's amount | POST /tenant/scan-pay/charge | | Collect | See links, per-link totals, collections, merchant code | GET /tenant/scan-pay | | Pay | Pay any Alphadome pay link (paste, upload a poster, or live camera) | POST /tenant/scan-pay/pay | | Pay (customer) | Open the link and prompt their own phone | POST /pay/t/:tokenId/intent | | Resell | Sell an airtime/data bundle to a customer's number | POST /api/kassangas/buy-product | | Resell | This tenant's own bundle sales + the catalogue + provider readiness | GET /tenant/scan-pay/bundles |

The tools around the wallet

QR, both directions. Create QR + link draws the poster code (public/vendor/qrcode.min.js through public/vendor/qr-poster.js) and Download QR saves that same PNG for printing. On the pay side the same jsQR decoder serves an uploaded screenshot and a live camera (getUserMedia, rear camera). The camera is released on decode, on "Stop camera", and before the section re-renders, so the light never stays on. With no camera or no permission the section says which of those happened and the paste field still works.

Both libraries live in public/vendor/ and are served from /vendor/... by the same Express app. The first build pointed the generator at https://cdnjs.cloudflare.com/ajax/libs/qrcode.js/1.5.3/qrcode.min.js, which answers 404, so QRCode was undefined on every load and the panel said "QR library unavailable — share the link instead". Self-hosting removes that failure mode; a CDN copy only loads if the vendored file is missing.

Why qr-poster.js exists. A QR that draws is not a QR that scans. qrcodejs fills its canvas with a fractional tile — a 33-module link asked for at 190px gets 190/33 = 5.76px per module — so every module edge lands on a half pixel and the browser anti-aliases it grey. It also draws edge to edge: no quiet zone, on a panel that is dark. A phone camera will not lock onto that, which is what "the QR is missing" actually looked like on 2026-10-27. qr-poster.js takes the module matrix from qrcodejs and redraws it with

  • a whole number of pixels per module (17px at the default 720px side),
  • four modules of white margin on every side, filled as the canvas ground,
  • the same bitmap handed to the screen and to Download QR.

Verified in the suite by decoding the poster against a near-black surround, the way the panel presents it; a margin-less code fails that test. The merchant portal uses the same helper, with api.qrserver.com still as the last-resort image.

Money tools. Two calculators on the same screen:

| Calculator | Inputs | Outputs | Carried over from | |---|---|---|---| | Sales | monthly target, already collected (prefilled with this tenant's Scan to Pay collections) | remaining gap, per day (30-day month), per week, already in | public/kassangas-merchant-portal.html | | Cash flow | monthly income, monthly expenses | net cash flow, savings rate, suggested 10% reserve, daily spend at that rate | public/kassangas-client-wallet.html |

The gap for the day/week is rounded up, so "KES 0 left" never ships while a shilling is still outstanding.

Airtime and data bundles. The bundle desk lists the same catalogue the Kassangas wallet sells from (data bundles, airtime, KPLC, water, GOtv/DStv, gift cards), shows the customer price, Alphadome's fee and what the tenant keeps before confirming, and sells through POST /api/kassangas/buy-product with merchant_code set to the tenant's own SP<digits>. Reads come from GET /tenant/scan-pay/bundles, which filters logs/digital_sales_transactions.jsonl by that same code, so one tenant never sees another's sales. The response also carries salesMode (sandbox / production) and each provider's readiness, so a "setup needed" provider is visible instead of being silently chosen.

The customer page (/pay/t/...)

The customer page carries no session: it resolves the link through GET /api/kassangas/template/:tokenId, then posts to the intent endpoint. It is marked noindex,nofollow and is not in sitemap.xml.

Reused, not rebuilt

  • kassangas_templates — the payment link (created by the live Kassangas portal).
  • subscriptions — the prompt, with plan_type = 'tenant_scan_pay'.
  • initiateStkPush() — the single STK implementation in server.js.
  • qrcodejs 1.0.0 and jsQR 1.4.0 — vendored in public/vendor/ (provenance and

    • licences in public/vendor/README.md), served at /vendor/....

  • qr-poster.js — our own 60-line renderer over qrcodejs' matrix: whole-pixel

    • modules and a quiet zone, so the code scans off a screen and off paper.

No migration is required to collect: both tables already exist wherever the Kassangas QR checkout runs. If kassangas_templates is missing, the routes answer 503 naming SQL_MIGRATION_KASSANGAS_PHASE1.sql instead of pretending to work.

Tenant isolation

  • Every link row carries metadata.tenant_id (the tenant's site_tenants.id) and

    • metadata.tenant_code.

  • GET /tenant/scan-pay lists links with a jsonb containment filter on that id and

    • collections with account_ref ILIKE '<merchantCode>%'.

  • POST /tenant/scan-pay/charge refuses a link that is not this tenant's.
  • POST /tenant/scan-pay/pay may pay any link (that is the point) and records

    • metadata.payer_tenant_id.

  • Payer phones are masked in the portal (2547***78).
  • GET /tenant/scan-pay/bundles filters the sales log by the tenant's own merchant

    • code and returns masked recipients only, so the bundle desk cannot read another tenant's sales.

Merchant code and reconciliation

tenantMerchantCode({ phone, slug }) = SP + last six digits of the tenant's phone (SP245555). Each prompt's M-Pesa AccountReference starts with that code, so a paybill statement line can be matched to the tenant that requested it.

Rules the bridge must hold

  • /cf/order is authenticated per tenant (shared secret in bot_tenants.metadata), never open.
  • Idempotent on cf_invoice_id — CF retries webhooks.
  • A funnel id that is not this tenant's is refused 404, same as /pay/t does.
  • STK double-tap inside 90 s replays the prompt, never sends a second one (utils/scanPay.js already owns that rule).

  • Do not buy or rent an aged Stripe account. It ends the processor relationship for every client hanging off it.

FALLBACK_PAYMENT_OPTIONS.md

FALLBACK_PAYMENT_OPTIONS.md

Fallback Payment Options Feature

Overview

When M-Pesa STK push payments fail or refund (while waiting for EPI connection approval from Safaricom), customers are automatically presented with alternative payment methods. This ensures revenue doesn't get blocked due to temporary M-Pesa gateway unavailability.

Current Status: Production-ready, enabled by default when M-Pesa ResultCode ≠ 0

---

Payment Flow Architecture

Standard M-Pesa Flow


Customer → POST /webhook "JOIN ALPHADOME" → initateStkPush() →
   STK prompt on phone → Customer enters PIN →
   M-Pesa processes → POST /mpesa/callback (ResultCode = 0) →
   Payment marked "subscribed" ✅

Fallback M-Pesa Flow (EPI Pending)


Customer → POST /webhook "JOIN ALPHADOME" → initiateStkPush() →
   STK prompt on phone → Refund after ~5 minutes (ResultCode ≠ 0) →
   POST /mpesa/callback → sendFallbackPaymentOptions() →
   WhatsApp Interactive List with 4 options → Customer selects

---

Fallback Payment Methods

1. 🔄 Retry M-Pesa

Trigger: Customer replies with "RETRY" or taps "Retry M-Pesa" button

Flow:

  1. System retrieves failed amount from session context
  2. Initiates new STK push with same amount/reference
  3. Updates user session with retry_checkout_id
  4. Sends confirmation message
  5. Waits for new callback on /mpesa/callback

User Message:


💳 Retrying M-Pesa payment for KES 500. Please enter your M-Pesa PIN on your phone...

Code:

  • Triggers: text.toUpperCase().includes("RETRY") or text.match(/retry.*mpesa/i)
  • Calls: initiateStkPush() again with saved context

---

2. 🏦 Bank Transfer

Trigger: Customer replies with "BANK" or taps "Bank Transfer" button

Flow:

  1. System sends bank transfer instructions with:
  • KCB Bank details (Account: Alphadome Limited)
  • Amount to send
  • Reference format: {plan_type}-{checkoutId.slice(-8)}
  1. Prompts customer to reply with receipt
  2. Customer replies: BANK RECEIPT K2P4A5B6C7
  3. System confirms receipt and marks subscription as manual_pending_verification

Bank Details Sent:


🏦 Bank Transfer Instructions

Amount to send: KES 500

Bank: KCB Bank Kenya
Account Name: Alphadome Limited
Account Number: 1234567890
Branch Code: 63000
Swift Code: KCBLKENX

📌 Important:
• Use Reference: monthly-ABC123DE
• Reply with the bank deposit receipt number
• Allow 2-5 minutes for confirmation

Code:

  • Triggers: text.toUpperCase().includes("BANK")
  • Receipt validation: /^BANK\s+RECEIPT\s+([A-Z0-9]+)$/i
  • Updates subscription to manual_pending_verification status

utils/scanPay.js

/**
 * Scan to Pay — the rules shared by the tenant merchant wallet and client wallet.
 *
 * The platform already runs a QR → M-Pesa STK flow for Kassangas
 * (`public/kassangas-merchant-portal.html`, `public/kassangas-client-wallet.html`,
 * `kassangas_templates`, `subscriptions`). Rather than build a second payment
 * engine, the tenant portal reuses that stack: this module owns the parts that
 * must agree everywhere (phone normalisation, link validation, the merchant code
 * a tenant's collections are stamped with, the pay URL, and the "table missing"
 * message that names the migration).
 *
 * Pure functions only: no express, no supabase, no env reads except the optional
 * `env` argument. `scripts/test_scan_pay.mjs` exercises every export offline.
 */

/** subscriptions.plan_type for every tenant scan-to-pay collection. */
export const PLAN_TYPE = 'tenant_scan_pay';

/** The QR-payment table the live Kassangas flow already writes to. */
export const TEMPLATES_TABLE = 'kassangas_templates';

/** The file a deployment must run once before links can be created. */
export const TEMPLATES_MIGRATION = 'SQL_MIGRATION_KASSANGAS_PHASE1.sql';

export const LINK_NAME_MIN = 2;
export const LINK_NAME_MAX = 120;
export const LINK_MIN_AMOUNT = 1;
export const LINK_MAX_AMOUNT = 300000;

/** Env vars `initiateStkPush()` needs before it can send a prompt. */
export const STK_ENV_VARS = [
  'MPESA_CONSUMER_KEY',
  'MPESA_CONSUMER_SECRET',
  'MPESA_PASSKEY',
  'MPESA_SHORTCODE',
  'MPESA_CALLBACK_URL',
];

/**
 * Kenyan MSISDN → 2547XXXXXXXX. Accepts 07XXXXXXXX, 7XXXXXXXX, +2547XXXXXXXX and
 * 2547XXXXXXXX. Returns the digits as given when they do not match, so the caller
 * can reject with one message instead of guessing.
 */
export function normalizeMsisdn(raw) {
  let v = String(raw ?? '').replace(/[^\d+]/g, '').replace(/^\+/, '');
  if (/^0[17]\d{8}$/.test(v)) v = '254' + v.slice(1);
  else if (/^[17]\d{8}$/.test(v)) v = '254' + v;
  return v;
}

/** Safaricom mobile number in the shape the STK endpoint accepts. */
export function isValidPayerPhone(raw) {
  return /^2547\d{8}$/.test(normalizeMsisdn(raw));
}

/**
 * The code a tenant's collections are reconciled against. Derived from the
 * tenant's own phone (the platform's tenant key), so it is stable across
 * deploys, unique per tenant and safe inside an M-Pesa account reference
 * (alphanumerics only — the existing Kassangas refs use hyphens, but a paybill
 * statement reads cleanest without punctuation).
 */
export function tenantMerchantCode({ phone, slug } = {}) {
  const digits = String(phone || '').replace(/\D/g, '');
  if (digits.length >= 9) return 'SP' + digits.slice(-6);
  const seed = String(slug || 'tenant').toLowerCase().replace(/[^a-z0-9]+/g, '').slice(0, 4) || 'tnnt';
  return 'SP' + seed.toUpperCase() + String(fnv1a(String(slug || phone || ''))).slice(0, 2);
}

/** FNV-1a, so the fallback code is deterministic and does not need a database. */
export function fnv1a(value) {
  let hash = 0x811c9dc5;
  const text = String(value ?? '');
  for (let i = 0; i < text.length; i++) {
    hash ^= text.charCodeAt(i);
    hash = Math.imul(hash, 0x01000193) >>> 0;
  }
  return hash.toString(36).toUpperCase();
}

/** One account reference per collection attempt. */
export function buildAccountRef(merchantCode, now = Date.now()) {
  const code = String(merchantCode || 'SP').replace(/[^A-Za-z0-9]/g, '').slice(0, 10) || 'SP';
  return code + Number(now).toString(36).toUpperCase();
}

/** The link a customer opens after scanning the poster QR. */
export function payUrl(baseUrl, templateId) {
  const base = String(baseUrl || '').replace(/\/+$/, '');
  return `${base}/pay/t/${encodeURIComponent(String(templateId || ''))}`;
}

/** A tenant may paste either the full link or the bare token. */
export function extractTemplateId(raw) {
  const s = String(raw ?? '').trim();
  if (!s) return '';
  const fromPath = s.match(/\/pay\/t\/([A-Za-z0-9_-]{4,120})/);
  if (fromPath) return fromPath[1];
  const fromQuery = s.match(/[?&]t=([A-Za-z0-9_-]{4,120})/);
  if (fromQuery) return fromQuery[1];
  return /^[A-Za-z0-9_-]{4,120}$/.test(s) ? s : '';
}

/** Human-readable template id, same shape as the live Kassangas flow. */
export function buildTemplateId(now = Date.now(), random = Math.random()) {
  const stamp = String(now).slice(-6);
  const tail = String(random).replace(/[^0-9a-z]/gi, '').slice(2, 8).toUpperCase().padEnd(6, '0');
  return `TMPL-${stamp}-${tail}`;
}

/**
 * Validate what the merchant typed before anything is written. Returns
 * `{ ok, error }` on failure and the cleaned values on success.
 */
export function validateLinkInput(input = {}) {
  const itemName = String(input.itemName ?? input.item_name ?? '')
    .replace(/\s+/g, ' ').trim();
  const amount = Number(input.amount);

  if (itemName.length < LINK_NAME_MIN) {
    return { ok: false, error: 'Give the payment link a name (at least 2 characters).' };
  }
  if (itemName.length > LINK_NAME_MAX) {
    return { ok: false, error: `Keep the name under ${LINK_NAME_MAX} characters.` };
  }
  if (!Number.isFinite(amount) || amount < LINK_MIN_AMOUNT) {
    return { ok: false, error: 'Enter an amount of at least KES 1.' };
  }
  if (amount > LINK_MAX_AMOUNT) {
    return { ok: false, error: `Amounts above KES ${LINK_MAX_AMOUNT.toLocaleString('en-KE')} need a bank transfer — contact Alphadome.` };
  }

  return {
    ok: true,
    itemName,
    // Safaricom accepts whole shillings only, so the amount the prompt carries and
    // the amount the ledger records have to be the same integer.
    amount: Math.round(amount),
    reusable: input.reusable !== false,
  };
}

/** Payer phones in the collections table are masked: the portal is not a phone book. */
export function maskPhone(phone) {
  const digits = String(phone || '').replace(/\D/g, '');
  if (digits.length < 6) return '';
  return digits.slice(0, 4) + '***' + digits.slice(-2);
}

/** A payment link as the portal renders it. */
export function shapeLink({ row = {}, baseUrl = '', stats = {} } = {}) {
  const templateId = String(row.template_id || '');
  return {
    templateId,
    itemName: String(row.item_name || ''),
    amount: Number(row.amount) || 0,
    reusable: row.reusable !== false,
    merchantName: String(row.merchant_name || ''),
    status: String(row.status || 'active'),
    createdAt: row.created_at || null,
    url: templateId ? payUrl(baseUrl, templateId) : '',
    paidCount: Number(stats.paidCount) || 0,
    collected: Number(stats.collected) || 0,
    pending: Number(stats.pending) || 0,
  };
}

const PAID_STATUSES = new Set(['completed', 'paid', 'success', 'succeeded']);

/** One collection row as the portal renders it. */
export function describeCollection(row = {}) {
  const status = String(row.status || 'pending').toLowerCase();
  return {
    id: row.id || null,
    amount: Number(row.amount) || 0,
    status,
    payer: maskPhone(row.phone),
    accountRef: String(row.account_ref || ''),
    itemName: String(row?.metadata?.item_name || ''),
    source: String(row?.metadata?.source || ''),
    createdAt: row.created_at || null,
  };
}

/** Totals for the merchant wallet header. */
export function summariseCollections(rows = []) {
  return (rows || []).reduce((acc, row) => {
    const amount = Number(row?.amount) || 0;
    const status = String(row?.status || '').toLowerCase();
    acc.count++;
    if (PAID_STATUSES.has(status)) acc.collected += amount;
    else if (status === 'pending') acc.pending += amount;
    else acc.failed += amount;
    return acc;
  }, { count: 0, collected: 0, pending: 0, failed: 0 });
}

/** Per-link totals, keyed by template id, from the collections rows. */
export function statsByTemplate(rows = []) {
  const out = {};
  (rows || []).forEach((row) => {
    const id = row?.metadata?.template_id;
    if (!id) return;
    const bucket = out[id] || (out[id] = { paidCount: 0, collected: 0, pending: 0 });
    const amount = Number(row?.amount) || 0;
    const status = String(row?.status || '').toLowerCase();
    if (PAID_STATUSES.has(status)) { bucket.paidCount++; bucket.collected += amount; }
    else if (status === 'pending') bucket.pending++;
  });
  return out;
}

/** True when the QR table has not been created in this deployment yet. */
export function isMissingTableError(err) {
  const code = String(err?.code || '');
  const message = String(err?.message || err || '');
  return code === '42P01' || code === 'PGRST205'
    || /could not find the table|relation .* does not exist/i.test(message);
}

export function missingTemplatesMessage() {
  return `Payment links need the ${TEMPLATES_TABLE} table. Run ${TEMPLATES_MIGRATION} in Supabase, then retry.`;
}

/**
 * What is missing before a prompt can be sent. The portal shows this instead of
 * letting `initiateStkPush()` fail with a generic "Missing required M-Pesa
 * credentials" after the tenant has already typed the customer's phone number.
 */
export function stkReadiness(env = {}) {
  const missing = STK_ENV_VARS.filter((key) => !env || !env[key]);
  return { ready: missing.length === 0, missing };
}

export function stkReadinessMessage(missing = []) {
  return `M-Pesa is not configured on this deployment yet (missing: ${missing.join(', ') || 'MPESA_*'}). Add the credentials in Render, then retry.`;
}
